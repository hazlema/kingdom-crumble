## Findings

### 1. P1 — Rotating large scenery produces images the loader refuses

**Locations:** `src/editor/scenery_bake.gd:61–69`, `:197–211`; `src/level/level_json.gd:77–81`; `src/editor/tools/scenery_tool.gd:166–176`.

The resize handle limits the unrotated image to 1,024 pixels per edge. Rotation then enlarges its bounding box. `_cap_image_to_max()` checks compressed base64 length only, while `decode_png_b64()` rejects dimensions above 1,024 or more than 1,048,576 pixels. Flat-color art compresses well enough to pass the byte cap even when it exceeds both decoded limits.

**Reproduction:** import square art, enlarge it to 800×800, rotate 45°, then Save or Test. A focused bake of that state produced a **1,132×1,132 PNG, only 18,916 base64 characters**. Serializing and parsing the level succeeded, but the shared image decoder returned null. The scenery builder consequently omits the piece. Baking also consumes its edit state and can erase the original image blob, so the editor has already lost the recoverable pre-bake state.

**Fix:** enforce decoded dimension/pixel budgets after rotation and before replacing the old blob. Either reject the operation while retaining pending edits, or downsample with a corresponding representation that preserves intended world size. Do not silently shrink the scene artwork.

**Regression check:** save/reload low-entropy square art at the maximum resize and several oblique rotations; assert the image remains decodable and visible.

### 2. P2 — Baking rotation changes placement for non-center pivots

**Locations:** `src/editor/scenery_bake.gd:61–95`, `:113–159`; `addons/narfkit/narf_decor.gd:112–119`.

The live preview rotates around the selected pivot, but the bake rotates pixels around the image center. It preserves the old overlay coordinates and pivot while discarding `_rot`. The resulting image therefore occupies a different world position. Save and Test both use this path.

**Reproduction:** place a 64×64 image at `(1000,400)`, select `LOWER_CENTER`, and rotate 90°. The live image center is `(1032,400)`; after baking and rebuilding it is **`(1000,368)`**. This is a geometric discrepancy, independently of rendering quality.

**Fix:** carry the transformed pivot/offset through the raster conversion and compensate placement. Preserve the animation anchor as well as the visible image bounds; changing only the displayed center can change subsequent sway/spin behavior.

**Regression check:** compare world-space geometry and animation anchors before and after save for corner/edge pivots, rotation, scaling, and flips.

### 3. P2 — Opening a level deletes props belonging to unavailable packs

**Location:** `src/editor/level_editor.gd:582–607`.

`_rebuild()` filters props through the currently enabled registry and writes the filtered array back into `current.props`. An absent or disabled pack therefore causes a document mutation during Load, even if the user only intends to edit an intro or unrelated crate. Saving commits that deletion. Restoring the pack afterward cannot recover those placements from the saved level.

**Reproduction:** load a valid document containing `missing:wall` with its pack absent. Calling the editor's normal rebuild changes the prop count from **1 to 0**. The only notice is a log warning. This also applies to a legitimately installed pack that the user disabled in the Toybox.

**Fix:** retain unavailable entries in the document and skip only their visual/physics instantiation. Show missing-dependency information or placeholders. Destructive cleanup should be an explicit author action.

**Regression check:** load, edit, and save with a pack disabled; re-enable it and verify all prop coordinates and animation settings survive.

### 4. P2 — Grid snapping leaves imported crate triggers at old coordinates

**Locations:** `src/editor/level_editor.gd:568–578`; `src/level/level_builder.gd:16–18`; compare the explicit migration in `src/editor/tools/grid_tool.gd:150–154`.

The JSON format permits coordinates between grid centers. Loading into the editor snaps every crate, but does not migrate its `hit:X,Y` trigger key. Gameplay then builds the crate's trigger identity from the new coordinates, leaving its authored actions unreachable. Dragging an existing crate correctly migrates the key; initial load does not.

**Reproduction:** a crate at `(833,443)` with `hit:833,443: [confetti]` is snapped to `(832,443)`. The trigger dictionary still contains **`hit:833,443`**, while the spawned crate answers to `hit:832,443`.

**Fix:** migrate keys using the original-to-snapped coordinate mapping before replacing the crate array. Handle collisions explicitly when multiple source crates snap into one cell.

**Regression check:** load and save an off-grid crate with show/sound/confetti actions; knock it out and verify those actions still fire.

### 5. P2 — Scenery file picker does not block polled editor input

**Locations:** `src/editor/scenery_panel.gd:22–29`; `src/editor/level_editor.gd:216–239`, `:286–300`.

The scenery panel creates its own non-native `FileDialog` but never registers it with the editor's popup registry or the menu's dialog registry. The editor keeps polling global mouse state. Window event routing alone does not stop this polling path—the reason the registry exists for other dialogs.

**Reproduction:** instantiate the editor, open `_file_dialog`, then ask `over_ui_at(Vector2(900,500))`. The dialog reports **visible=true**, while the editor reports **blocked=false**. In scenery mode, gestures over the file picker can consequently select or drag artwork underneath when the corresponding world point contains a piece. The registry omission is runtime-confirmed; a physical desktop click-through walkthrough remains to be checked.

**Fix:** register this dialog with the same central blocking mechanism and ensure any pending canvas drag is ended when a dialog opens.

**Regression check:** open Add Image while scenery is under the dialog; mouse press/move/release must leave selection, coordinates, and transforms unchanged.

### 6. P2 — Toybox admits prop IDs that cannot be saved

**Locations:** `src/level/pieces.gd:166–174`; `src/level/level_json.gd:33`, `:187–189`.

Object-pack scanning validates the folder name but uses the PNG basename verbatim. The level codec restricts prop IDs to lowercase letters, digits, underscore, colon, and hyphen, with a 64-character total limit. Thus an uppercase, spaced, or sufficiently long PNG basename can appear in the palette and be placed, but makes the level unsavable.

**Reproduction:** create `auditpack/Wall.png` with a sidecar `{"class":"static"}` and a valid object-pack manifest. Scanning registers **`auditpack:Wall`**. A document containing that prop is rejected with **`prop 0: bad id`**.

**Fix:** use one shared ID validator at registry admission and serialization. Reject unsupported filenames with a useful warning before offering them in the palette; avoid silently normalizing names without a collision strategy.

**Regression check:** scan uppercase, spaced, and overlong filenames; every selectable prop must survive a save/load round trip.

### 7. P2 — Disabling a pack changes powerups in the current level

**Locations:** `src/level/pieces.gd:397–401`; `src/level/powerup_rules.gd:17–18`; `src/ui/pause_menu.gd:123–126`, `:182–184`.

The pause menu says changes apply on the next level load, but toggling a pack immediately rescans and replaces the global registry. Existing crates keep their sprites and type IDs, while knockout reward routing consults the new registry. Disabling their pack strips their rewards during the already-running level. Re-enabling a pack can similarly change the behavior of an existing fallback crate.

**Reproduction:** register a pack crate with `powerup: free_shot`. Routing its type returns **refund**. Call `Pieces.set_pack_enabled(folder,false)` as the pause menu does; routing the same type now returns **none**. No level reload is involved.

**Fix:** defer registry changes until level transition, or snapshot gameplay metadata onto spawned crates and use that metadata for their lifetime. Keep preference changes separate from current-level behavior.

**Regression check:** disable an object pack during play, resume, and collect an already-spawned bonus crate. Its current-level reward should be unchanged; subsequent loads should honor the new preference.

### 8. P2 — Input size caps are applied after whole-file allocation

**Locations:** `src/level/level_store.gd:87–91`; `src/level/pieces.gd:100–104`, `:181–190`, `:240–245`; `src/editor/level_editor.gd:475–486`.

Level files are read completely and parsed before field limits are checked. Pack manifests and sidecars likewise use `get_file_as_bytes()` before testing their 64 KB cap; user PNGs have no encoded-file-size cap. Browser level upload calls `FileReader.readAsText()` without checking `File.size`. A large file therefore allocates its full contents before rejection. `LevelChain.entries()` also loads every user level, making an oversized file in that directory affect routine menu/start navigation.

**Evidence:** source-confirmed ordering of full reads, JSON parsing, and later limits. No memory-exhaustion experiment was performed. Existing PNG dimension checks correctly address decoded bitmap amplification, but do not bound encoded files or the initial JSON parse.

**Fix:** check file length before reading, impose a total level-document budget consistent with supported embedded images, and check browser `File.size` before reading. Add encoded PNG caps. Consider aggregate pack budgets as well as per-file limits.

**Regression check:** oversized fixtures should be rejected before full reads/decode; keep valid maximum-sized levels accepted.

## Limits and remaining manual checks

This is a broad source and headless-runtime audit, not an exhaustive proof of correctness. No desktop visual walkthrough, physical touch-device session, browser/PWA run, fresh platform export, or sustained performance profile was performed. In particular, thumbnail rendering exits early under headless mode, and web upload/download/fullscreen/service-worker behavior needs real-browser validation. GPU particles, visual clipping with large trigger lists or many Toybox packs, and portal behavior across frame rates merit manual checks.

The testing-build progress reset is explicitly enabled in the current project and documented as intentional; it is not treated as a bug. Verify that build setting when preparing a non-testing release.

Recommended fix order: address the two scenery bake defects first, then preserve imported document data and protect file-picker interactions, then align Toybox admission/lifetime rules and input budgets. Add the targeted regression cases above before relying on the green suite as coverage for these paths.
