# Toybox (Pieces Wave 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drop-in content packs: `user://toybox/<pack>/` folders holding object packs (new namespaced pieces) and theme packs (seasonal reskins of base art), with a player-facing Toybox section in the pause menu.

**Architecture:** Four tasks. (1) Pack discovery: manifest parsing, namespaced object-pack pieces via the runtime Image path, `user://toybox.cfg` persistence, season math with a test clock. (2) Theme resolution: one-active-theme texture override in `texture_for` with dimension guards and boot revert. (3) The Toybox UI in the pause menu (checkboxes, theme radio, out-of-season teases). (4) Sweep + docs (parts.md gains its Toybox chapter).

**Tech Stack:** Godot 4.6.3, GDScript, GUT headless.

## Global Constraints

- Godot binary: `/home/frosty/Dev/godot/bin/godot`
- Full suite (baseline **355 passing**) after every task: `godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests -ginclude_subdirs -gexit`
- **DEPLOY FREEZE: commit locally only. NO push/export/deploy.**
- Spec: `docs/superpowers/specs/2026-09-05-pieces-design.md` §5 + the 2026-09-06 amendments. `parts.md` is the canonical sidecar schema.
- Manifest `pack.json`: `title` String cap 60; `kind` ∈ `objects|theme`; `months` Array of ints 1–12 (absent/empty = always in season). Malformed manifest or unknown kind → named `push_warning`, pack ignored. A folder with NO pack.json → ignored with a warning (explicit beats guessing).
- Object packs: ids namespaced `<folder>:<basename>` (folder charset gate `^[a-z0-9_-]{1,32}$` — else warn+ignore pack; namespaced ids already pass the props validator's `a-z0-9_:-`). Disabled pack → pieces absent from registry → palette hides them, levels warn-skip at spawn (existing doctrine, zero new code).
- **user:// files are NOT imported resources**: pack PNGs load via `FileAccess.get_file_as_bytes` → PNG magic-byte check → `Image.load_png_from_buffer` → dimension cap (reuse `LevelJson.MAX_IMAGE_DIM` = 1024 per side) → `ImageTexture.create_from_image`. NEVER `load()` on user:// paths; never let hostile bytes reach the loader without the magic gate (thumb-pipeline lesson: `load_png_from_buffer` spams engine errors on junk — gate first).
- Theme packs: PNGs named for BASE ids only; art dimensions MUST equal the base texture's exactly → else named warning + that id falls back to baked. At most ONE active theme (`[theme] active` in toybox.cfg; "" = Default). Out-of-season active theme reverts to Default at scan time with a warning. Seasonal gating affects SELECTABILITY only — never playback of existing content.
- Persistence: `user://toybox.cfg` owned by Pieces (per-domain pattern beside progress.cfg/unlocks.cfg): `[packs] <folder> = true|false` (default true), `[theme] active = "<folder>"`.
- Season clock: `Time.get_date_dict_from_system().month`, overridable via `Pieces.clock_month := -1` (test seam; -1 = system).
- Headless tests write fake packs under `user://toybox/` — MUST clean up completely in the same test (shared real user dir — the settings-stomping lesson), including `toybox.cfg` keys they touch (capture-and-restore).
- Web: `DirAccess.open("user://toybox")` failing/absent = empty pack list, zero errors (desktop-first; web zip import is future).
- GUT counts engine errors as failures; deliberate warn-path tests only.
