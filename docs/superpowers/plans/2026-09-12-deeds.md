### Task 1: The Deeds autoload — manifest, cfg, triggers, signal

**Files:**
- Create: `src/settings/deeds.gd` (autoload `Deeds`, registered in project.godot AFTER VersionGate)
- Modify: `project.godot` (autoload entry), `src/settings/version_gate.gd` (WIPE_FILES gains `user://deeds.cfg`)
- Test: `tests/unit/test_deeds.gd` (new)

**Interfaces (produces — Tasks 2-4 rely on these exact names):**
- `Deeds.bump(stat: String, by: int = 1) -> void` — increments `[stats]` counter, saves, re-evaluates.
- `Deeds.flag(name: String) -> void` — sets bool stat true, saves, re-evaluates.
- `Deeds.is_unlocked(id: String) -> bool`
- `Deeds.entries() -> Array[Dictionary]` — validated manifest entries in file order, each with keys `id, name, text, solid, ghost, trigger, secret` (ghost may be "" = auto).
- `signal deed_unlocked(id: String)` — emitted once per id ever (celebrated-diff), in manifest order when one write unlocks several.
- `Deeds.cfg_path: String` — injectable for tests (default `user://deeds.cfg`).
- `Deeds.manifest_path: String` — injectable for tests (default `res://achievements/achievements.manifest`).
- `Deeds.reload() -> void` — re-reads manifest + cfg (tests and future toybox use).
- Evaluation: a trigger clause per Global Constraints; `count` supports ONLY `>=`; `unlocked:` requires ALL ids, load-time cycle/self-reference detection disables the entry with a warning naming it.
